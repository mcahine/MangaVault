# 库格式契约（LIBRARY_FORMAT）

> **这份文件是数据与代码之间唯一的接口定义。**
> 代码只认格式，不认来源。任何满足本契约的目录，加入 libraryRoots 即可被系统完整管理。
>
> 实现真源：`src/modules/library/scanner.mjs`。这份文档与它必须保持一致；改代码就要改这里。

---

## 1. 基本概念

| 概念 | 定义 |
| --- | --- |
| **库根（root）** | 一个磁盘目录，登记在 config.libraryRoots[]。系统可以有任意多个。 |
| **漫画（comic）** | 库根的**一级子目录**。这是系统的最小管理单元。 |
| **章节（chapter）** | 漫画目录下的子目录（含图片），或漫画目录本身（裸形态）。 |
| **正文图（page）** | 章节目录里的图片文件。 |
| **封面（cover）** | 漫画目录下的 cover.jpg（或 png/webp）。**不属于正文**。 |

目录名以 . 或 _ 开头的一级子目录会被**跳过**（用于放你自己的杂物）。

---

## 2. 四种合法形态

系统对漫画目录的识别是**宽容的**：信息越少，功能越少，但**永远能被识别和阅读**。

### L2 · 规范形态（信息最全）

```
<库根>/<漫画目录>/
├── 元数据.json             ← 可选，有则信息最全
├── cover.jpg               ← 可选封面
├── 1 第1話/
│   ├── 章节元数据.json      ← 可选
│   ├── 001.jpg
│   └── 002.jpg
└── 2 第2話/
    ├── 001.jpg
    └── 002.jpg
```

特点：有标题/作者/标签/点赞数，章节有正式顺序与标题，阅读器能显示章节列表。

### L1 · 多章无语义形态

```
<库根>/<漫画目录>/
├── 1/            ← 目录名只有数字也行
│   └── *.jpg
└── 2/
    └── *.jpg
```

特点：章节顺序取自目录名开头的数字，标题取去掉数字后的剩余部分。
没有数字就按目录名字典序并自动编号。

### L0 · 裸形态（单章）

```
<库根>/<漫画目录>/
├── 001.jpg
├── 002.jpg
└── cover.jpg     ← 会被排除出正文
```

特点：整本漫画当**一章**处理，章节标题默认「第1話」。
**这是"先期漫画"目录 53 部作品的形态。**

> ⚠️ 关键规则：只有当漫画目录下**没有任何含图的子目录**时，才把顶层图片当正文。
> 只要存在含图子目录，顶层散图就会被视为杂物而不计入正文。
> 这条规则是为了避免"封面/预览图"把整本书稀释成奇怪的章节结构。

### L1+ · 深一层形态（旧结构兼容）

```
<库根>/<漫画目录>/<分类目录>/<章节目录>/*.jpg
```

特点：漫画目录的子目录下没有直接图片，但再下一层有，则自动提升为章节。用于兼容早期整理过的目录树。

## 3. 元数据规范

### 3.1 漫画元数据 元数据.json

文件名固定为 元数据.json，UTF-8 JSON。**整个文件是可选的**；缺省时从目录名推导标题，其余字段留空。已知字段（未知字段会被忽略并保留在磁盘上）：

| 字段 | 类型 | 缺省行为 | 用途 |
| --- | --- | --- | --- |
| id | string | d-<目录名短哈希> | 漫画稳定标识；缺失时按目录名生成 |
| title | string | 目录名 | 显示标题 |
| author | string | 空 | 作者，参与搜索与排序 |
| tags | string[] | 空 | 标签，参与标签系统与筛选 |
| categories | string[] | 空 | 分类（与 tags 分开统计） |
| description | string | 空 | 简介 |
| chineseTeam | string | 空 | 汉化组，参与搜索 |
| pagesCount | number | 实际图片数 | 声称页数（用于校验） |
| likesCount / viewsCount | number | 0 | 排序用 |
| createdAt / updatedAt | ISO string | null | 排序用 |
| chapterInfos | ChapterInfo[] | 空 | 章节元数据内联，见下 |
| thumb | object | null | 远程封面描述（见 3.3） |
| creator | object | null | 作者信息（name / avatar） |

ChapterInfo 结构：

```jsonc
{ "chapterId": "63121750f06b112a1075926d", "chapterTitle": "第1話", "order": 1 }
```

### 3.2 章节元数据 章节元数据.json

放在**章节目录内**，可选。优先级：章节元数据.json > 元数据.json 的 chapterInfos（按 order 匹配）> 目录名推导。

```jsonc
{ "chapterId": "...", "chapterTitle": "第2話", "order": 2 }
```

### 3.3 封面解析优先级

1. 漫画目录下的 cover.jpg / cover.jpeg / cover.png / cover.webp（本地，最快）
2. 元数据.json 的 thumb.fileServer + thumb.path 拼出的远程 URL（需下载，未缓存时由前端回退占位符）
3. 都没有 → 前端显示首字占位块

## 4. 图片与排序

- 扩展名白名单见 src/core/util.mjs 的 IMAGE_EXT（jpg/jpeg/png/webp/gif/bmp/avif 等）。
- 文件排序用**自然序**（naturalCompare）：001 < 002 < 010，H2 < H10。不要依赖操作系统的字典序，否则 10.jpg 会排到 2.jpg 前面。
- 章节排序用 order 字段；无 order 时用目录名开头的数字；再没有就按目录序自增。

## 5. 健全度分级

系统用分级告诉用户"这本还缺什么"，而不是拒绝服务：

| 级别 | 条件 | 缺失能力 |
| --- | --- | --- |
| **A · 完整** | 有元数据 + 有封面 + 有章节结构 | 无 |
| **B · 可用** | 有元数据或有封面，章节结构正常 | 元数据/封面之一 |
| **C · 裸本** | 无元数据、无封面，图片直接在目录下 | 标题/作者/标签/封面 |
| **D · 异常** | 0 张图 / 图片全损坏 / 目录不可读 | 需人工介入 |

scripts/normalize-library.mjs 负责把 C 级升到 B/A 级：

1. 从目录名解析标题（去掉技术后缀，见下）
2. 生成 元数据.json（含 id / title / pagesCount / chapterInfos）
3. 取首图生成 cover.jpg（等比缩放到宽 600，JPEG 质量 82）
4. 全程 **dry-run 优先**，实际写入前要求 --apply

### 5.1 标题规范化规则

先期漫画的目录名带有整理工具留下的哈希后缀，例如 3D作品集（619dde41）、ミツカ CG集（60d1511f）。规范化规则：

1. 去掉末尾成对的 （8-16 位十六进制）
2. 折叠连续空格、去掉首尾空格
3. **保留**（单行本）、[中国翻訳]、（哔咔版）这类有语义的标注

> 判定：括号内若是纯十六进制且长度 >= 8，视为技术后缀删除；否则保留。

## 6. 接入一个新来源的完整流程

```powershell
# 1) 把目录放进任意位置（不需要放仓库里）
# 2) 在界面「设置 → 库根」添加，或直接改 data/config.json
# 3) 扫描
#    界面上点「扫描库」，或：
node scripts/scan-library.mjs

# 4) 如果来源是裸形态，跑规范化把它升级到 A/B 级（先预演）
node scripts/normalize-library.mjs --root=early
node scripts/normalize-library.mjs --root=early --apply
```

**不需要改任何代码。** 如果你发现某个合法目录结构无法识别，那是 scanner 的 bug，应当修 scanner.mjs 并同步更新本文件，而不是给这个来源写特例。

## 7. 明确不支持 / 边界

- **压缩包不自动解压**：.zip / .cbz / .rar 不会被扫描器递归展开。（导出模块会**生成** cbz，但扫描器不读它。）
- **不做内容识别**：不判断图片内容，不做 OCR，不自动打标签。标签只来自元数据与用户手动覆盖。
- **不跟随符号链接**：避免扫描失控进入系统目录。
- **扫描是纯读操作**：不修改用户原有结构（除规范化脚本显式执行外）。
- **目录名中的 < > : " / \ | ? * 在 Windows 上本就非法**，无需处理。
